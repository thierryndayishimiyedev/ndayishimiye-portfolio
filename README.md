# Thierry NDAYISHIMIYE — Developer & Artist Portfolio

A responsive personal portfolio for **Thierry NDAYISHIMIYE**, an Information Technology student at Rwanda Polytechnic, Karongi College, software developer, and independent artist known as **lost_ooh**.

🌐 **Live portfolio:** https://ndayishimiyeportfolio.netlify.app/  
💻 **GitHub:** https://github.com/thierryndayishimiyedev  
✉️ **Email:** thierryndayishimye100@gmail.com

## What the site includes

- Personal introduction and professional positioning
- Selected projects with repository links and expandable project notes
- Interactive employee directory and pharmacy stock prototypes using sample data
- Updated 2026 CV PDF with current education, skills, and selected projects
- Technical skills grouped by area
- Education and learning journey
- Artist identity and creative links
- Downloadable CV (the PDF must remain in the repository root)
- Email and WhatsApp contact actions
- Responsive mobile navigation, keyboard Escape support, and reduced-motion preferences
- SEO description, social preview metadata, canonical URL, and Person structured data

## Built with

- HTML5
- CSS3
- Vanilla JavaScript

## Run locally

Open `index.html` in a browser, or use a local static server such as VS Code Live Server.

## Interactive prototypes

- `demos/employee-management.html` — searchable sample employee directory with add-record interaction and browser-local persistence.
- `demos/pharmacy-stock.html` — searchable sample inventory with low-stock filtering and add-item interaction.

These are front-end portfolio demos with fictional sample data, not production systems or live backends.

## Keep it accurate

Project notes describe the general purpose of each project without claiming unverified features. Update the project cards when a repository has a confirmed live demo, screenshots, or new features. Keep the CV PDF filename in sync with the download links in `index.html`.

## Deployment

The site is a static website and can be deployed through Netlify by connecting this GitHub repository. Changes pushed to the production branch should trigger a new deployment when continuous deployment is enabled.
